# Session Log — 2026-10-23

## Overview

Shared desk phones shipped. A handset is now set up once as itself, and staff log in to it from their extension
(`*50` + extension) and log out again with `*51`, instead of their calls being tied to a personal SIP login. Six PRs
(#42–#47) were merged and deployed on 2026-10-23, each only once Twilio showed no live calls. Five Hume handsets and one
Wagga handset were converted. Personal SIP logins were demoted to an admin-only option.

## What shipped

- **#42 Shared desk phones (`services/person_devices.py`, `services/sip.py`, `database/db.py`, migration 083).**
  - A phone is a SIP user named `desk_<make>_<last 6 of MAC>` (for example `desk_polycom_592E3A`). The name carries no
    store, so a phone can move between sites without the name lying.
  - `*50` + extension logs a person in to the phone. `*51` logs them out. Logging in at one phone moves them off any
    other phone.
  - One answer each way: `db.get_staff_email_for_sip_username` (phone login → person) and `sip_uri_for_person`
    (person → desk phone; a shared phone wins over a personal one). Outbound caller ID, the call log, the answering agent
    and transfer targets all read these.
  - An empty shared phone still calls out on the tenant default number.
  - Offboarding logs the leaver out of any shared phone.
  - Admin → Desk phones shows who is on each phone, lets an admin set it in place, and adds shared phones.
- **#43 Phone screen (`/phone-screen/<tenant>/<user>/<token>`).** Drives the idle screen on a desk phone. The URL carries
  an HMAC token and the route is exempt from tenant resolution. It is served over plain HTTP through the nginx file
  `rinq-phone-screen`, because the older Polycom firmware cannot complete a Let's Encrypt TLS handshake.
- **#44 Bare `*50`** announces who is currently on the phone.
- **#45 "Number when nobody's on it"** is a per-phone setting (`users.default_caller_id` on the phone row). The picker
  shows an inactive occupant. Yealink line labels are served from `/phone-screen/.../prov/<MAC>.cfg`, which sets only
  `account.1.label`.
- **#46 Yealink label** is the occupant's first name, or "Nobody" when the phone is empty.
- **#47 My Devices demoted.** `/my-devices` is now the staff "My settings" page (caller ID, what rings, which shared phone
  you are on). It is off the menu and linked from the caller-ID footer on the Phone page. It no longer creates SIP
  credentials on its own. Admin → Desk phones has a "Personal phone logins" section with a picker that creates one for
  a person (`_ensure_personal_sip_credential`), for people who use Zoiper. The VVX 300 setup guide moved to admin-only
  `/desk-phones/vvx300-setup` and was rewritten for shared phones.
- **Handsets converted.** Hume: Polycom 592E3A (.196), 592AFF (.130, Jay), 592E03 (.162), 64A6AC (.198); Yealink 9B53E8
  (.160). Wagga: Yealink 9B5967, done from the Wagga PC. Extensions switched on for Maricris, Katrina and Jay.

## Decisions

- **No PIN on `*50`.**
- **One person, one phone at a time.** Logging in at a new phone moves the person off the old one.
- **Name the phone by make and last six of the MAC,** not by store.
- **Personal SIP logins stay available but are admin-issued only.** The PWA only rings while it is open, so it is not a
  reliable primary device, and staff are not sent off to create their own.
- **Firmware upgrade skipped.** The Poly download site returns 403 and the upgrade adds nothing the current firmware
  lacks.

## Discoveries

- **VVX 300 has no idle browser by default.** Screen saver type "Idle Browser" with Microbrowser Idle Display set to Home
  works.
- **VVX web field names differ by firmware.** Map fields by their label, not by position or internal name.
- **One Save on the VVX applies every page visited.** Check each page before saving.
- **Second-hand handsets still carry the old VoIP Cloud provisioning** (Yealink auto-provision pointed at
  `pbx3.au.voipcloud.online`). Always replace a second-hand handset's provisioning rather than assuming it is clean.
