# Session Log — 2026-10-13

## Overview

After-hours release (Sydney evening) of three phone-page fixes for the queue panel and the Transfer box, all in
`rinq/web/templates/phone.html`. Three PRs, each merged and deployed green. Before each merge there was a check that
no calls were open on do-personal; HEAD was verified after each deploy and `rinq` was active.

## What shipped

- **PR #23 `queue-answer-while-on-call`** (merge `53daa8c`) — `isOnActiveCall()` added. While the browser phone is
  open, connecting, ringing or reconnecting, every queue Answer button reads "On a call" and is disabled, and
  `answerQueueCall` bails before doing anything.
  - Cause: on 2026-10-13 at 15:46 (call_log 75928) an agent clicked Norman Munro's row while Chelsea Williamson's call
    was ringing. The July fix correctly connected and labelled Chelsea. The agent then clicked Answer on Norman
    again mid-call. The no-pending path ran `fetchCustomerContext(Norman)` before `device.connect`, the SDK refused the
    second call, and the catch set the status to "Ready". The screenshot showed Norman in the Customer panel with a
    "Ready" pill during a live call.
- **PR #24 `queue-answer-ringing-row`** (merge `c959557`) — `ringingQueueCallSid()`. While a ring is pending and its
  `From` matches exactly one waiting caller, the other rows show a disabled "Waiting". Any doubt keeps every Answer
  button enabled: no ring, `From` under 6 digits, a shared number, or a non-queue ring. This is follow-up #1 from
  July. Render-tested in Node (11 cases). Derek ran a live dual-SIM test on Test Queue and it passed.
- **PR #25 `transfer-hold-note`** (merge `1a4324a`, commit `99d530d`) — the Transfer box note. Opening Transfer has
  auto-held the caller since `a2bce0d` (2026-04-30), but the orange note still said "The caller can still hear you
  while you choose a target". The note now has id `transferHoldNote`, and `updateHoldButton` sets it: green "The
  caller is on hold and can't hear you." when held, orange warning otherwise.

## Decisions

- Derek prefers the auto-hold-on-Transfer behaviour. The customer should not hear the agent choosing a target, so the
  note was changed to match the behaviour, not the other way round.
- Rinq changes went out after hours, with an open-calls check before each merge.

## Issues

- **Queue-answer click mismatch is still happening.** The `queue-answer-click-mismatch` diagnostic fired 13 times
  between 29 Sep and 13 Oct (Shristi 5, Jacinta 4, Suzette 4). That is a lower bound. PR #23 and #24 are the fix for
  it.
- **Test Queue (id 8) `max_wait_time` is still 10** from the July test. Left as is.
- **Lesson:** the first answer about hold and transfer behaviour came from the stale UI label, not from reading
  `openTransferModal`. The handler was read afterwards. Read the handler, not the label.
- No automated tests were added. The Node render checks were run ad hoc and are not in the repo.

# Session Log — 2026-10-13 (later the same evening: Reports, Tina Says, cross-check)

## What shipped

- **PR #26:** `_agentHungUp` flag in `hangupCall`/`endCall`. "Caller hung up" no longer shows when the agent ended the call.
- **PR #27:** Reports counted unanswered callers only for managers' own team.
  - `include_all_callers=user.is_manager`.
  - The stale-ringing sweep now marks untouched inbound rows `ended_early`, not `missed`, and skips callers still in `queued_calls`. Rows before 2026-10-14 used `missed`.
- **PR #28:** caller outcomes, made per caller instead of per leg.
  - Adds `get_caller_outcomes` and `get_queue_outcomes`.
  - The hourly chart is now DST-correct.
  - Manager cards now read Incoming / Answered / Voicemail (with how many left a message) / Hung Up Waiting / Hung Up Early.
- **PR #29:** one row per call.
  - Adds `ONE_ROW_PER_CALL_SQL` and `TALK_SQL`. Rows over 4h count as 0, and outbound talk is capped at connected time.
  - Agent stats exclude internal calls.
  - The leaderboard shows active staff only.
  - The outbound customer-leg row is now closed.
  - `daily_call_stats` is keyed `'__all__'`. Before, a NULL key duplicated a row every 15 minutes; the table is unread.
- **PR #30:** Tina Says, a daily one-liner strip on the phone page (migration 081, `services/tina_says.py`, `GET /api/tina-says`).
  - Facts are computed from clean data only (`TRUST_FROM` 2026-08-01).
  - `check_line` drops any line whose number or name isn't in its fact.
  - Templates are the fallback.
- **PR #31:** weekly Tina-vs-Twilio cross-check (`services/cross_check.py`, `POST /api/stats/cross-check`). Cron runs Sunday 20:00 UTC on do-personal.
  - The first run found 38 of 55 unanswered outbound calls stored as answered: `voice_call_ended` overwrote a recorded non-answer.
  - Fixed: `NOT_ANSWERED_STATUSES` is now kept, and talk time is credited only for answered calls.
- **PR #32:** CLAUDE.md gotchas 41–42 and the cross-check cron added to the docs.
- **ANTHROPIC_API_KEY** copied from do-work's shared `.env` into `/var/www/rinq/.env` (backup `.env.bak-20261013`), approved by Derek. Then a manual `rinq` restart.
  - A read-only dry run on live data produced 12 Claude lines with no errors.
  - 10-13's stored run stays on templates; Claude writes the lines from 10-14.
- **PR #33** (`f0c4b9a`): Tina Says never uses he/she for staff. This is a prompt rule, plus a `check_line` regex that drops the line.

## Decisions

- Staff are named publicly only for good news. Tina never guesses pronouns: names or they/them. Derek floated per-user pronoun settings; not built.
- The cross-check emails every week, even on a pass, so silence means it's broken. "Couldn't run" is never a pass. The derek tenant emails only on problems.

## Issues / lessons

- An inline Python heredoc turned `\b` in a regex into a literal backspace byte. As written, the pronoun check would have blocked every line containing "the". It was caught by `cat -A` and a sample test before shipping. Write scripts to a file first.
- Inbound `voicemail` status means *sent to* voicemail. A message exists only if there is a `recording_log` voicemail row (93% do).
