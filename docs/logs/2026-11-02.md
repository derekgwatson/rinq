# Session Log — 2026-11-02

## Overview

Tina went down on Monday 2 Nov 2026 from about 9:00 to 9:21 Sydney. Incoming callers heard Twilio's
"an application error has occurred". Fixed the same day in PR #89 (merge `b3983ba`), deployed 22:21 UTC.
The fix is verified on prod.

## What happened

- Every tenant DB query uses `with self._get_conn() as conn:`. sqlite3's context manager commits but never
  closes the connection, so handles piled up.
- Since Sunday's move to do-rinq (Python 3.14), those handles were not freed promptly.
- Gunicorn workers hit the 1024 open-file soft limit. From then on `sqlite3.OperationalError: unable to open
  database file` was raised in `master.py` `get_tenant` during tenant resolution, so every request failed.
- A restart at about 9:15 cleared it. Under business-hours load (phone pages polling `/api/queue/*` every few
  seconds) all three workers were back at 1023 open files within about 15 minutes.

## Fix

- **PR #89:** `Database._get_conn()` now calls `sqlite3.connect(..., factory=_ClosingConnection)`. Its `__exit__`
  commits or rolls back, then closes.
- `tests/test_db_connections_close.py` (3 tests). Full suite: 87 passed, 2 xfailed.
- **Verified on prod:** open-file counts flat at 7–12 per worker, and 0 errors after 5 minutes of live traffic.
