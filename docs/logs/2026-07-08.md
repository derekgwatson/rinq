## The real fix — per-queue "voicemail if no one answers"

**Problem Derek raised:** when Chris (desk phone, never watches the browser
dashboard) doesn't answer, the caller drops into the hold queue and rings his
unwatched desk until `max_wait_time` (~5 min) finally dumps them to voicemail.
Not workable. This is DIFFERENT from Canberra (12 browser agents watching the
dashboard) where holding is correct — a freed agent grabs the held caller. So it
needed to be **per-queue**, not global.

**Root cause of "holds forever":** in the conference auto-ring model, each agent
ring leg has a status callback to `queue_agent_ring_status` (routes.py ~2415).
It only acted on `busy` (explicit reject). A `no-answer` (desk phone rings out
after the leg's 30s timeout) just removed the ring attempt and returned OK — no
give-up path, so the caller kept holding.

**Fix:** new per-queue flag `voicemail_on_no_answer` (migration 078, default 0).
`queue_agent_ring_status` now also acts on `no-answer`/`failed` (ring-out): when
the flag is set and the LAST agent leg rings out with none remaining, it calls the
existing `_send_queue_caller_to_voicemail()`. That helper no-ops unless the caller
is still `waiting`, so a call another agent answered can't be bounced by a stray
canceled-leg callback. `completed`/`canceled` are ignored (they're torn-down legs
after someone answered). Flag off = unchanged hold-and-wait, so Canberra is
unaffected. Admin queue create/edit forms get a checkbox (wired via `_update_row`
present-keys-only — no default-clobber). Enabled on Batemans Bay (2), Wagga (4),
Shoalhaven (5); off for Canberra (3) and Test Queue (8).

Note: auto-ring hardcodes `timeout=30` per leg (not `queue.ring_timeout`), so the
bounce fires ~30s after entry. Continuous re-ring is default-off on these queues,
so nothing re-rings after the ring-out.
