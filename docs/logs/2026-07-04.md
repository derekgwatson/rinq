## Decisions and WHYs

### Phase 0 — live bugs first (ba8f1ef)
Seven confirmed-live bugs fixed before anything structural:

- Missing `import json` in `admin_schedule_routes` — saving a schedule with
  business hours failed with a NameError that flash-only error handling hid.
- `phone.html`'s monkey-patched `fetchQueueCallers` had dropped the DND check.
- Callback "Call Back" claimed the callback but never dialled — it targeted a
  nonexistent `#dialNumber` element and `makeCall(phone)`'s argument was
  ignored.
- Undeclared global `consultTargetAnswered` now declared + reset.
- `get_twilio_config()` called inside a spawned ring thread killed PSTN forward
  targets (no tenant context in threads — CLAUDE.md gotcha 2).
- Blind transfer now cancels the still-ringing target leg if the customer
  redirect fails, instead of leaving it ringing into nothing.
- `/setup` page gated behind `admin_required`.

### Phase 1 — security and tenant isolation (a30e1cf)
- **X-Twilio-Signature validation** on the unauthenticated voice/SIP webhooks.
  Controlled by `RINQ_TWILIO_SIGNATURE_MODE`, currently **LOG mode** — flip to
  enforce after watching logs for false negatives.
- Tenant middleware now does a membership check on domain adoption;
  `get_current_user` **denies** instead of defaulting to `role=user` when no
  `tenant_users` row exists.
- Tenant-leak singletons removed: `TransferService._base_url` capture deleted,
  Drive folder-ID cache un-pinned (per-tenant), sip domain `_none` cache slot
  removed.
- CLI `setup-tenant` no longer copies master `TWILIO_*` env creds — full
  `provision_tenant()` by default.
- `phone.html` escapes customer/caller/queue names into innerHTML and
  transfer-target onclick args (XSS via caller-supplied names).
- Voicemail ticket requester email is now per-tenant via bot_setting
  `voicemail_requester_email`.

### Phase 2a — kill the default-clobber updater pattern (fd39ab0)
The June `ring_timeout` bug (see 2026-06-29 log) was a *class*, not an instance.
New `db._update_row()` helper writes **present keys only**; the seven
`data.get(key, default)` clobber-prone updaters were replaced with it. The audit
found more live clobbers of the same shape: **every queue save reset
`welcome_audio_id`, `callback_reminder_audio_id`, `position_announcement`, and
`announcement_interval`**, and the daily Peter sync reset `hide_mobile`.
Also: `twilio_list(raise_on_error=True)` at transfer decision points, so a
transient Twilio API error returns a retryable error instead of falsely failing
the transfer with "caller disconnected".

### Phase 2b/3 — thread context that actually works (5922337)
`capture_for_thread()` **never worked** — it stored into `threading.local`,
which by definition doesn't cross thread boundaries. Every background thread
silently used the master Twilio account. This was masked in production because
watson IS the master account. New `start_twilio_thread()` re-binds the tenant
account inside the spawned thread; all 13 spawn sites converted; the
master-credential fallback now logs a warning so any future leak is visible.
Plus: ~60 silent exception handlers now log (new `web/util.py` `flash_error()`
helper covers 40 web handlers), `_is_queue_paused` datetime comparison fix, and
identity encode/decode dedup.

## Key discoveries

- **`capture_for_thread()` was a no-op** — `threading.local` doesn't cross
  thread boundaries, so tenant capture never happened. Only safe today because
  the sole active tenant (watson) is the master account.
- **The default-clobber pattern was live in five more places** beyond the June
  ring_timeout case — queue audio/announcement fields and `hide_mobile` were
  being silently reset. The fix prevents *future* resets; values already lost
  are not restored.
- **Flash-only error handling hides NameErrors** — the Phase 0 schedule bug
  survived because the except path flashed a generic message and swallowed the
  traceback.
